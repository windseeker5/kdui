Two different responsibilities

Application developer

Uses the Python generator and finished UI assets. Does not need npm.

Flask Starter maintainer

Maintains Basecoat, Tailwind, components, the gallery, generator, and compiled assets. Needs Python and npm.

Step 1

Prepare the maintainer workspace

Clone once, then install both Python and UI build dependencies.

git clone https://github.com/windseeker5/kdui.git flask-shadcn-starter
cd flask-shadcn-starter

python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt

npm ci
python wsgi.py

npm ci installs the exact locked versions. Its post-install step synchronizes Basecoat and rebuilds the committed CSS. Open http://127.0.0.1:5005/ui/.

Step 2

Update before starting work

git status
git switch main
git pull
npm ci
{{ alert(message="Do not pull over uncommitted work. Commit it, stash it, or use a separate branch first.", title="Start clean") }}

Create a focused branch for one change:

git switch -c add-contact-avatar

Step 3

Add or improve a component

Build reusable UI from a real application need, not an abstract guess.

  1. Check existing components and Basecoat before creating anything.
  2. Prototype and test the UI in a real Flask application.
  3. Remove business names, routes, database code, and application-specific assumptions.
  4. Create a documented Jinja macro in app/templates/components/.
  5. If browser behavior is required, add a same-named file in app/static/js/components/.
  6. Add a generic, copyable example to app/templates/gallery/components.html.
app/templates/components/contact_avatar.html
app/static/js/components/contact_avatar.js     # only if needed
app/templates/gallery/components.html          # live example + usage

A reusable macro should accept its content as parameters, support multiple instances, and usually provide a class_="" layout override.

Bring a proven component back from an application

The promotion helper copies one explicitly named component into this local repository.

# Compare first; changes nothing
python scripts/kdui_promote.py status \
  --source /absolute/path/to/application \
  --kind component

# Preview one copy; changes nothing
python scripts/kdui_promote.py component contact_avatar \
  --source /absolute/path/to/application \
  --dry-run

# Copy into the local Flask Starter repository
python scripts/kdui_promote.py component contact_avatar \
  --source /absolute/path/to/application

The helper never commits, pushes, edits the source application, or updates the gallery. Review and generalize the copied code yourself.

Step 4

Rebuild and test the component

npm run build:css
python wsgi.py

The CSS rebuild is mandatory after adding or changing Tailwind classes. Flask debug reload does not compile CSS.

Finally, generate a temporary application and copy the component into it to test the consumer workflow:

rm -rf /tmp/kdui-smoke
python scripts/kdui.py new /tmp/kdui-smoke
python scripts/kdui.py add component contact_avatar --target /tmp/kdui-smoke

Separate maintenance task

Update Basecoat safely

Do this deliberately—not as part of every component change.

# See whether a newer release exists
npm outdated basecoat-css

# Update package.json and package-lock.json
npm install basecoat-css@latest

# Copy Basecoat templates, JavaScript, and CSS; then compile output.css
npm run build

npm run build copies Basecoat Jinja macros to app/templates/basecoat/, JavaScript to app/static/js/vendor/, source CSS to app/static/css/, and rebuilds output.css.

{{ alert(message="A dependency upgrade can change markup or browser behavior. Test every Basecoat-powered gallery example, especially sidebar, dialog, dropdown, tabs, select, combobox, toast, popover, and dark mode.", title="Treat upgrades as their own change") }}

Step 5

Review before publishing

npm run build
git diff --check
git status
git diff

Commit only the intended component, optional controller, gallery example, documentation, dependency files, and generated assets. The helper tools never commit or push automatically.

Maintainer workflow in one line

Update → branch → reuse Basecoat → build in a real app → generalize → gallery demo → rebuild → test generated app → review → publish.
